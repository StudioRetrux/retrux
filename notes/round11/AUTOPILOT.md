## Heartbeat procedure
1. Run `zsh pipeline/r11_status.zsh` and read "Current state" below.
2. Workflow RUNNING and every active agent wrote within the last 45 min: reply with one status line, nothing else.
3. Workflow COMPLETED with FAILURES > 0 of any kind (usage limit, network ENOTFOUND / can't reach the API, other API errors): first
   update the RESUME NOTEs in the script for the steps that were cut off (what their LOG.md says they finished and what is next;
   never touch prompts of agents that completed, or they re-run). The resume cache is PREFIX-based in call order: once one call
   re-runs (a failed or edited one), every later call re-runs too, even unchanged completed ones. To keep a completed result that
   comes later in the order (e.g. a judge verdict), inject it into the script as a constant and skip that agent() call
   (done for judge:hold as HOLD_V1). Verify with the hash harness ($SP/wfcheck/cmp2.mjs pattern) before resuming. Then resume it now with `Workflow({scriptPath, resumeFromRunId, args})` from
   "Current state" (completed agents replay from cache), then update "Current state" (new task id).
4. Workflow COMPLETED with no failures but "Current state" still says it is running: process its result (the phase's
   "on completion" step), then start the next phase.
5. An agent STALE? (no write for > 45 min while the workflow runs): read the tail of its transcript before doing anything;
   long Blender or capture runs can be quiet. Never kill what is working.
5b. Power mode: user idle > 30 min AND on AC -> slot full power ({n:3, loadMax:16, bg:false}); otherwise light ({n:2,
   loadMax:400, bg:true}). Battery < 25 % and unplugged -> refresh lane_backup every heartbeat.
6. caffeinate OFF: restart it (`caffeinate -i -m -s`, background). :5173 or :3000 not listening: restart them
   (`cd retrux-web && npm run hero:lab` / `npm run dev`, background).
7. After any action: update "Current state" and append a line to "Log".
